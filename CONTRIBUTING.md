# Contributing

## Workflow
- Branch from `main`, open a pull request, and let CI pass before merging.
- Keep pull requests to one area (one screen, one skill, one scene set).
- Run `npm test` locally. For one area, run only its suite, e.g. `npm run test:browser today`.

## Where things go
- App code is edited only in `app/`. Never edit `plugin/skills/study-setup/assets/app/`; it is generated by `npm run build:plugin` and ignored by git.
- Each screen keeps its CSS in `app/css/<area>.css`. `app/index.html` holds the shell and design tokens only.
- `app/core/store.js` is the only module that talks to the database. Database changes go through `app/SCHEMA.md` first and need a migration in `store.js` plus a test in `tests/engine.test.mjs`.
- A new scene is one `app/scenes/<id>.js` plus one line in `app/scenes/manifest.json`.
- A new recording goes in `app/audio/`, with a line in `manifest.json` and its source and license in `LICENSES.md`. Only CC0 or public-domain recordings.

## Code style
- Plain ES modules, no build step, no runtime dependencies.
- Code, identifiers, comments and docs in English. Student-facing text in Hebrew, following [docs/hebrew-style.md](docs/hebrew-style.md).
- Skills never invent course content, dates or grades.

## Personal data
Never commit real study data: database exports, backups, syllabi, grades, course materials, screenshots of a real account. Tests and screenshots use the fictional data in `app/core/mock.js`. `.gitignore` blocks `*backup*.json` as a safety net.
